**Goal:** Give gotrader a live source of trades and quotes, durably buffered in Redpanda so that many strategies and tools can consume the same market data stream without each of them holding its own vendor connection.

## Context

Today gotrader only reads market data from files: `IBZippedCSV` and `ZippedCSV` produce candles from CSV, and `GenericParquetTrades` produces `MarketEvent` from parquet dumps. Every feed is historical, so a strategy can be backtested but never run against the live market. There is also no fan-out point: whoever wants the data must open its own connection to the vendor and re-implement parsing, so two processes watching the same ticker pay twice and can disagree on what they saw.

## Objectives

**Functional goal:** A quant developer configures one struct with a Massive API key, the tickers to follow and the Redpanda brokers, and gets every trade and quote for those symbols written to a topic named after the ticker. From there any number of consumers — a live strategy, a recorder, a monitoring tool — read the same stream independently. The pipeline reports, per ticker, how much it received and wrote, how long each hop took and how many errors it hit, so the operator can tell a quiet market from a broken feed.

**Architectural goal:** A new `massive` package holds the whole integration, split into two independently callable functions joined by a channel: an ingester that owns the vendor SDK and produces `MarketEvent`, and a producer that owns the Kafka client and writes to Redpanda. That seam is what makes each half testable alone and what keeps the vendor SDK from leaking into the framework types. The package creates OTel instruments on the global meter but never configures a provider or an exporter, because gotrader is a library and the process owner does that wiring. Nothing outside the new package changes except a documentation note on `TickFeed`, whose strict ordering contract a live multi-partition feed cannot honour.

## Impacted architecture

| Container / component | Impact |
|---|---|
| `massive` (new package) | Config, ingester, mapping, Redpanda producer, tick feed, metrics |
| `tickfeed.go` | Documentation note: `MassiveTickFeed` relaxes the ordering contract to non-decreasing `TS` per ticker |
| `go.mod` | New dependencies: `massive-com/client-go/v3`, `twmb/franz-go`, `go.opentelemetry.io/otel` |
| `tick.go`, `datafeed.go` | Unchanged — `Trade`, `Quote` and the parquet layout are not touched |
| External: Massive.io WebSocket | New outbound dependency, reached only through the vendor SDK |
| External: Redpanda | New outbound dependency, one topic per ticker, auto-created |
